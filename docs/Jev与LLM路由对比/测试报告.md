# Jev 与 LLM 路由耗时对比测试报告

报告版本：1.0；日期：2026-10-26；任务：JLC-04 / JLC-05。主运行：`jlc04-formal-live-20261026-203132-2b882a`。

## 1. 结果与结论范围

在隔离 Java 路由链路、413 条人工构造样本各重复 3 轮的对比中，Jev 加 LLM 回退相对 DashScope qwen-plus 主路由，整体 P50 从 **405.94 ms 降至 211.59 ms（降低 47.88%）**，P95 从 **722.19 ms 降至 536.62 ms（降低 25.69%）**。路由阶段 LLM 逻辑调用从 1239 次降至 49 次，减少 **96.05%**；主准确率为 **94.75% → 98.47%**。

数据支持本次指定环境中观察到的路由耗时降低。用户要求“仅报告数据，暂不判定达标”，故接受状态为 **NOT_EVALUATED / USER_REPORT_ONLY**，不作业务达标或上线决定。这里计时覆盖路由决策服务，后续业务 Agent 生成回答未执行；没有聊天首字、完整回答耗时、生产流量、高并发或货币成本收益证据。

## 6. 回退、错误与瓶颈证据

正式 Jev 组直接采用 **1190/1239 = 96.05%**，实际尝试 LLM 回退 **49/1239 = 3.95%**。其中 42 次得到正常 LLM 回退决策，7 次 LLM 非法路由枚举后进入安全默认；失败回退没有漏算为“未调用 LLM”。Jev 子调用有 1 次 INVALID_RESPONSE；最终原因 LOW_CONFIDENCE=41、INVALID_RESPONSE=1、LLM_ERROR=7（LLM_ERROR 会覆盖先前 Jev 原因，不能把最终原因表当完整 Jev 子原因分布）。

基线 15 次、Jev 回退 7 次均记录为 INVALID_LLM_ROUTE_RESULT；采集器未保存模型原始输出正文，无法进一步核对具体非法字符串。没有观测到认证、额度、限流或传输异常；仅凭本次记录不能保证这些问题不会发生。所有请求的 RestClient attempts 之和等于 Jev+LLM 逻辑调用之和，未观测额外应用层执行尝试；底层重连、网络重传及供应商计费不可由此断言。

Jev 直接采用子集 n=1190，P50/P95=210.67/299.90 ms；尝试回退子集 n=49，P50/P95=661.90/874.59 ms。回退路径尾部更高，是本次可定位的慢路径；子集输入难度不同，不能将其差值解释成纯回退额外成本。代理、服务区域、连接复用和缓存可能影响结果，目前缺少阶段证据，只能列为下一实验变量。

建议下一轮先在 development 上核对上述非法输出及 4 组标签争议，固定新版本后对保留集复测；若验证应用层收益，再另行准备隔离 Redis/数据库与真实 Advisor/会话更新链路；若研究尾延迟，先增加子阶段计时并单变量比较网络出口/连接策略。本轮不修改策略，也不新增真实调用。
