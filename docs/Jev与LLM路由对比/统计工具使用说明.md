## 2. 校验与返回码

| 返回码 | 含义 |
| --- | --- |
| 0 | 成功生成完整统计，或正确生成未执行的 DRY_RUN 计划报告；不代表性能优化已通过 |
| 2 | JSON、schema、身份、重复键、额外记录、静态字段、计划哈希、状态、计数或进度结构不合法；生成前缀加 `-diagnostic.json` 的诊断文件 |

输入 JSON 的重复字段、NaN/Infinity、负耗时、布尔值冒充整数身份均拒绝。两组各自的不同 configId 是合法设计，但不得混入第三套组别/配置或更改计划中的字段。完整运行的总逻辑调用数、可知的 HTTP 计数必须与逐请求数据一致。

`DRY_RUN` 为 PLANNED/未执行，准确率为 null，不以 0 分冒充模型失败。SYNTHETIC 可以数据完整，但始终带模拟警告，不得作为真实性能收益。原始 JSONL 缺失或破损按输入问题处理，不自动修补。

## 3. 指标

主准确率以计划正式请求为分母，只有 OK 且正确计对；安全默认、错误、中断、缺失均计错。另列最终标签匹配率，以揭示 KNOWLEDGE 兜底可能带来的表面匹配。

全量耗时统计包含已经结束且耗时精确的 OK、SAFE_DEFAULT、ERROR；未知值保持 null，另列正常子集和耗时缺失数量。使用 nearest-rank：排序后取第 ceil(p×n) 项。总体分位数从原始请求重算，不平均各轮分位数。P99 为探索性指标。

回退尝试率从 Jev 组 `llmCallCount>0` 统计，包括回退后安全默认；来源和回退原因另列。逻辑 LLM 调用减少比例只有完整观察时作为完整指标提供，部分运行只保留明确命名的已观察值。它不等于费用减少比例。

JSON 包含逐轮、开发/保留集、四类 Agent、tags、历史、多意图和争议场景切片，四类 Recall、正常决策混淆矩阵及逐样本配对。配对包括错误/兜底，不只筛两边成功。重复轮次不增加独立样本数或场景组数。

清单中的源文件哈希是历史运行身份；统计程序不会把它替换成当下工作区哈希，也不会因未来合法改动强制抹掉过去的证据。实际计划文件需与 manifest 中的 `scheduleSha256` 一致。报告同时记录输入文件与当前报告协议的哈希，便于识别协议版本变化。

## 5. 已核验的模拟数据

上游 fixture 的每组正式计划数均为 20：LLM 组 17 个正常结果、3 个安全默认，Jev 组 18 个正常结果、2 个安全默认。两组正常正确数都为 4，因此主准确率都为 0.2；LLM 组若只按最终标签匹配会得到 0.25，说明安全默认必须单列。Jev 组实际 LLM 尝试 14 次、直接采用 6 次。
