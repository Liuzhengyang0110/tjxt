协议 ID：`jlc-protocol-v1`；记录 schema：`route-benchmark-v1`；日期：2026-10-26（Asia/Shanghai）。任务 JLC-01：DOC_COMPLETE；静态验证 PASS；live NOT_RUN。用户已授权协议、代码和本地验证及后续串行实施；真实 API 环境、调用上限、预算和成功判据仍为 PENDING，由根会话在 JLC-02/03 完成后集中确认一次。本协议不构成真实 API 批准。

协议机器版为本目录 `protocol.json`，固定样本为 `smoke-ids.json`，审计摘要为 `dataset-audit.json`，逐条审阅结果为 `sample-review.jsonl`；自然语言与机器版存在分歧时停止运行并修订版本，不能自行猜测。指南 v1.0 第 3.3/3.4 节是共同记录及统计的约束。

## 1. 比较问题和唯一入口

比较当前普通 LLM 主路由与 Jev 门控加同一 LLM 串行回退的整体路由延迟及分类质量。两组均调用真实 `FallbackRouteDecisionService.decide(question, sessionId)`，返回 Agent 后结束；不得调用下游业务 Agent、工具或 `/chat`。

| variant / configId | provider | shadow | fallback | Jev enabled | 阈值 |
| --- | --- | --- | --- | --- | --- |
| LLM_PRIMARY / llm-primary-v1 | LLM | false | true | true，但本路径不调用 | 不参与判断 |
| JEV_WITH_FALLBACK / jev-fallback-085-v1 | JEV | false | true | true | 默认 0.85，各类覆盖为空，包括 BUY |

两组各用独立、固定配置实例，串行交替调用；禁止在共享单例中并发切 provider。两组 LLM 模型、动态系统提示词、固定输出协议、Advisor、记忆窗口、超时、重试和日志设置相同。Jev Java 阈值 0.85，`confidenceThresholds={}`；Python 工具的独立 BUY 门槛不能冒充 Java 已生效配置。调参只在开发集，以新 configId、新哈希、新计划和预算执行。

外层紧邻 `decide` 调用前取得 `System.nanoTime()`，正常返回或抛出后立即结束，`latencyMs=(end-start)/1_000_000.0`。异常路径也必须记录。该时间包含上下文构建、当前真实 Advisor、网络、SDK 重试、门控、串行回退、服务内部指标及日志调用。历史装载、会话准备、清理、结果写盘、固定间隔均在边界外。服务内日志的计时止于记录日志前，不能与外层数字混算。异步日志后台刷新不保证被外层完整覆盖，记录实际实现。

全 Jev 组均纳入比较，包括失败、回退和 SAFE_DEFAULT；不能用 Jev 直接采用子集代替。可靠观测不到子阶段时 `jevMs/llmMs=null`；不能将两个模型的独立 P95 相加当成回退 P95。

## 2. 环境与隔离适配

主实验为 `ISOLATED_JAVA_ROUTE`：复用真实 RouteAgent、路由服务、Jev 客户端、DashScope 模型客户端及 `SpringAIConfig` 的 ChatClient/Advisor 构建。仅会话更新改为内存测试适配，记忆持久化改为同时实现 `ChatMemoryRepository` 与 `MyChatMemoryRepository` 的内存仓库。保留 `MessageWindowChatMemory(max=100)`、记忆 Advisor 和原 `RecordOptimizationAdvisor`；优化契约是识别路由返回后删除本会话最后两条路由消息。测试必须验证预置历史不会被清理串扰，非法输出等失败路径也会在最终清理中释放本次会话。

每条 `(round, sampleId, variant)` 使用唯一测试会话、同一测试用户；两组从同一原始 history 分别装载，当前 question 只发送一次。先设置线程 UserContext，再装载历史；结束后清理该会话和线程上下文。Jev 保留当前截断和脱敏（4000 字符、最近 8 条，当前问题优先），LLM 保留当前 100 消息窗口；原始输入相同不等于有效 token 相同，因此结论是两套实际路由方案的客户端耗时比较。

此模式不启动完整应用、不访问 Nacos/Redis/数据库；动态提示词使用用户提供的、与实际 RouteAgent 一致的本地受限快照，注入原 `SystemPromptConfig` 引用后通过真实 `RouteAgent.systemMessage()` 生成完整系统提示词。不能把缺少动态配置时只剩固定输出协议的结果标为当前基线。固定协议与动态快照均保存 SHA-256，实测前后核对。

`APPLICATION_ROUTE` 是后续条件扩展：需要单独指定及授权隔离部署、Redis/DB/Nacos 与受限入口，保留真实会话及持久化行为；本次默认不运行。两个层次独立报告，不把内存适配结果称为线上全链路证据。

## 4. 固定调度与预算提案

调度种子 `20261026`；每轮使用 `seed+round` 打乱原始样本 ID（round 从 1 开始）。实现必须将完整 schedule 在请求前写盘，算法、语言和版本记入 manifest；后续恢复以该 schedule 为准，不跨语言重算随机序列。轮内按洗牌位置和轮次奇偶交替 AB/BA，A=LLM_PRIMARY，B=JEV_WITH_FALLBACK；`orderIndex` 为全 run 从 0 开始的连续调用索引，`pairOrder` 为 AB 或 BA。并发 1；相邻路由结束后固定等待 250ms（计时外）。每轮先预热每组 10 次，预热使用独立 sampleId，例如 `warmup-r1-LLM_PRIMARY-01`，关联 `inputSampleId`；按固定冒烟清单循环取输入，两组输入对应一致。预热不计正式统计但计预算。

| 阶段 | 正式路由 | 预热路由 | Jev 逻辑调用上限 | LLM 逻辑调用上限 |
| --- | --- | --- | --- | --- |
| 冒烟：20 条 × 2 组 × 1 轮 | 40 | 20 | 30 | 60 |
| 正式：413 条 × 2 组 × 3 轮 | 2478 | 60 | 1269 | 2538 |
| 合计提案 | 2518 | 80 | 1299 | 2598 |

总路由上限 2598、供应商逻辑调用上限 3897。最坏每次 Jev 请求都回退；基线和回退共享 LLM 调用上限。以上不包含新增调参和重复现场测试，不预留自动重跑额度。SDK 内 HTTP 重试必须启动前核实；无法观测实际尝试次数则记录 null，不能拿逻辑上限冒充 HTTP/账单上限。若用户要求硬 HTTP 次数上限，必须配置并验证重试边界或直接禁用 SDK 自动重试，形成显式测试配置差异，由用户确认。

预算币种、金额、当前单价、token 上限与重试策略均 PENDING，不猜测成本。必须实现路由/供应商逻辑调用硬上限及停止条件；预算不可观测时不宣称程序能按金额精确拦停。鉴权/地区系统故障、连续不可恢复错误、配置漂移、超过批准上限、存在外部业务写入或无法约束的超时，应停止新增请求，保留已取得数据。硬总超时若中断不支持取消的同步客户端，不能立即继续请求导致重叠。

## 5. 输出 schema 与统计契约

输出目录：`tj-aigc/target/route-benchmark/<runId>/`（已核对被 Git 忽略）。runId 使用上海时间加随机后缀；manifest 同时保存 UTC 和 Asia/Shanghai 时间，明确 `mode=DRY_RUN/LIVE/SYNTHETIC`，三者隔离。预运行生成 `manifest.json` 与 `schedule.jsonl`；逐计划写 `requests.jsonl`，结束生成 `summary.json`、`summary.md`、`execution.md`。未开始项允许不写 requests，由 schedule 对账为 missing。已经开始但中断保留 INTERRUPTED，未知 latencyMs 为 null。恢复不能以同一唯一键静默再调一次；不确定完成与否时记录中断，重试需新增 attemptId 设计或新 runId 并保留原证据。

requests 的必须字段：`schemaVersion, runId, configId, environmentLevel, round, sampleId, variant, orderIndex, pairOrder, warmup, expectedAgent, actualAgent, source, fallbackReason, confidence, latencyMs, status, errorType, jevModel, llmModel, jevCallCount, llmCallCount, startedAt, finishedAt`。同时记录 `mode, scenarioGroupId, split, tags, inputSampleId`；可观测时记录 `jevMs, llmMs, httpAttemptCount, retryCount`，未知为 null。时间用 ISO-8601 含时区；latencyMs 使用单调时钟。唯一键为 `(runId, configId, round, sampleId, variant, warmup)`。

`status=OK/SAFE_DEFAULT/ERROR/INTERRUPTED`；source 取真实决策的 `LLM_PRIMARY/JEV/LLM_FALLBACK/SAFE_DEFAULT`，无返回为 null。fallbackReason 取真实枚举，无返回可以 null；外层异常仅记录脱敏异常类型，不输出问题、内部 URL、完整堆栈或密钥。SAFE_DEFAULT 返回 KNOWLEDGE 也不能算正常正确。

逻辑调用数必须从实际客户端/服务边界观测，不能仅由 source 推算：Jev 调用前上下文错误可能使 jevCallCount=0，但仍回退；LLM 失败后 SAFE_DEFAULT 的 llmCallCount 仍为 1。低置信回退的最终 RouteDecision 会清空 confidence 和 Jev model，不能由最终对象伪造原 Jev 子结果；可用受控包装器记录子调用元数据。LLM RouteDecision.model 为 null，需从模型有效配置及响应元数据获取；未知则保留 null 并禁止声称已核实模型。

manifest 必须包含协议/schema/runId、环境/mode、源码与数据/动态及完整提示词哈希、两组配置 ID 和安全摘要、实际模型和参数、超时/代理/重试/日志、JDK/SDK/系统版本、调度种子/算法/间隔、计划数量、已批准限额及批准状态、适配器差异、已知限制、开始/结束时间。来源码摘要基于 HEAD 加工作区哈希，不只写提交号；源码静态哈希见 `protocol.json`。禁止在 manifest 写密钥、认证头、带凭据 URL 或原始用户问题历史。

统计采用指南 3.4：nearest-rank 全组已完成且有精确时长记录（含回退、SAFE_DEFAULT、已结束错误）计算 P50/P95/P99，另列 OK 子集。主准确率=`status=OK 且标签正确/计划正式请求数`，失败/安全默认/缺失均计错；另列仅标签匹配率。四类 Recall 同样按计划类别为分母。总体分位数从所有原始时长重算，不平均三轮 P95；逐轮、总体、development/holdout、复杂场景分别展示。配对记录不能只筛双 OK；丢失/重复/中断都显式计数。缺耗时不填 0。结构错误非零退出；INCOMPLETE 只能给部分结果，不产出正式达标结论。

回退尝试率用实际尝试 LLM 的 Jev 组计划请求数为分子；LLM 逻辑调用减少比例=`1-Jev组LLM逻辑调用总数/基线组LLM逻辑调用总数`，不是费用比例。改善=`(LLM分位数-Jev分位数)/LLM分位数`，基线为 0 时 null，负数保留。没有价格与用量时成本 null。
