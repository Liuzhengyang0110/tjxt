## 2. 复用范围与基线

两组使用独立固定 RouteProperties/JevProperties，调用真实 `FallbackRouteDecisionService.decide`。LIVE 保留真实 `JevClientConfig`、`JevDecisionClient`、`JevRouteDecisionService`、`LlmRouteDecisionService`、`RouteAgent`、DashScopeChatModel，以及 `SpringAIConfig` 构造的 ChatClient、日志/记忆/记录优化 Advisor。LLM 通过真实 RouteAgent 加载动态快照并追加原固定输出协议；不启动 SpringBoot，不读取 Nacos，不连接数据库或 Redis。

会话 `update` 是只允许该方法的 no-op 测试适配器。内存仓库同时实现 `ChatMemoryRepository` 与 `MyChatMemoryRepository`，保持删除最后两条路由消息的契约。每次使用独立会话、同一测试用户及原 history，当前问题只发送一次。finally 只清该会话和线程上下文。UserContext 与 Servlet 请求上下文设在实际请求线程，原自定义 RetryListener 正常工作。没有业务 Agent、工具或 `/chat` 调用。

LLM 可配置 `model/temperature/topP/topK/maxTokens/enableThinking/enableSearch/seed`。未显式提供的参数不冒称已确认的服务端默认值；清单分别保留配置摘要与模型构造后的 `runtimeClientOptions`，null 表示未由客户端明确指定，服务端默认未知。响应型号单独记录，首次非空型号冻结，后续变化停止；供应商别名解析与配置型号允许不同。usage 可从响应取得时保留，缺失不伪造 token。

重试复用 Spring AI 1.0.0 官方 `SpringAiRetryAutoConfiguration.retryTemplate/responseErrorHandler`，只重试官方定义的 TransientAiException。原自动配置默认：最多 10 次，指数退避初始 2000ms、倍数 5、最大 180000ms；客户端错误默认不重试。可通过 `retryMaxAttempts/retryInitialIntervalMs/retryMultiplier/retryMaxIntervalMs` 显式覆盖，清单标明是否偏离原默认。示例采用原默认，网络超时示例只是待确认值。默认外层单条截止 30000ms；若保留长重试策略，应明确批准足够的 routeTimeoutMs，否则慢请求会使本次实验停止且结果标 INCOMPLETE，不能用这种中断制造提速结论。

## 3. 安全边界、计数和中断

外层用 `System.nanoTime` 紧邻包围真实 decide，包括串行回退和已结束错误；历史装载、清理、写盘、间隔在外。每组全部记录都应纳入后续统计，不能只取成功 Jev。逻辑调用计数来自真实 Jev 客户端与 LLM service 调用入口，包含失败，不由 source 推断。

两供应商同步 RestClient 共用计数器与上限，每次执行尝试均先检查全局 STOP；Spring AI 应用层重试也经过该拦截器。`httpAttemptCount` 的精确定义是 **RestClient 拦截器实际放行的执行尝试数**，不是供应商到账请求数；JDK 网络栈内部重连、TCP 重传无法观察。不能宣称物理 HTTP 或金额硬上限。`retryCount=null`，不从 HTTP 与逻辑调用数差值伪造 SDK 重试数。金额/token 总预算由批准政策与账号侧约束处理，程序不冒称能按价格精确拦停。

在 run 目录创建空 `STOP` 文件可阻止后续逻辑/HTTP 发起；当前已发请求不保证撤销。单条外层截止或线程中断时先不可逆关闭所有后续供应商发起权限，再 cancel；即使 Jev 因中断进入原回退逻辑，也不能开始 LLM 请求。停止后不创建新工作线程、不继续采集。中断记录 latencyMs/finishedAt/httpAttemptCount 为 null，保留已观察到的逻辑调用数、httpAttemptCountObservedAtStop 及 completionUnknown。未知时长不记 0。

中断时优先使用 worker 保存的实际 decide 开始时刻；若 worker 尚未到达该边界，`startedAtSemantics=SUBMISSION_ONLY_ACTUAL_START_UNKNOWN`，`startedAt` 仅为提交时刻，同时保留 `submittedAt`、`actualRouteStartedAt=null`，不能据其推算请求耗时。正常记录的 startedAt 是实际 decide 边界。

鉴权/地区失败、系统故障导致的 SAFE_DEFAULT、实际响应型号变化、配置或源码漂移、达到上限时停止新请求。已经结束的 LLM 非法路由枚举输出标为 `INVALID_LLM_ROUTE_RESULT`，仍以 SAFE_DEFAULT 计入错误与质量统计，继续采集；不能把单条模型输出不合规误当作整个服务不可用。该区分在首次正式采集误停后修正，21 项本地组件测试通过，原不完整运行保留。

源文件/数据/协议/配置/提示词与采集器源码/编译文件哈希会检查漂移；LIVE 开始前还要求生产源码与冻结协议一致。读取或初始化错误仍需审阅 execution/manifest；未知结果不得自动付费重试。

## 4. 文件与记录

产物：`tj-aigc/target/route-benchmark/<runId>/manifest.json`、`schedule.jsonl`、`schedule-sha256.json`、`requests.jsonl`、执行时的 `progress.jsonl` 与 `execution.md`。清单和完整计划先写盘，逐条 JSONL flush；run 目录原子创建，已存在一律拒绝，唯一键也拒重。汇总由 JLC-03 单独完成。

必填字段完全沿用协议。附加字段：`mode/scenarioGroupId/split/tags/inputSampleId/ambiguous/multiIntent/hasHistory/jevMs/llmMs/httpAttemptCount/retryCount/jevErrorType/llmErrorType/llmResponseModel/jevConfidence/llmUsage`。不可观测子阶段耗时为 null。`jevModel/jevConfidence` 是受控观察器保存的子调用值，包含因回退被最终对象清掉的原始元数据；非法输出也可保留其自报型号，不代表结果有效。

status 为 `OK/SAFE_DEFAULT/ERROR/INTERRUPTED`。原始异常只保留类型或 Jev 枚举，不写异常响应体、认证头或完整问题历史。脚本用独立 logback 配置保留路由 INFO 日志、关闭可能打印异常响应体的官方重试监听日志与详细请求日志；两组相同。该日志差异在 manifest 记录。

不支持自动续跑：强杀进程可能留下 progress 的 STARTED 且无最终记录。其完成状态未知，必须保留证据、人工核对、使用新 runId 和重新授权的预算；不得把它静默重发。标 INCOMPLETE 的运行保留已生成记录，由 JLC-03 按 schedule 发现缺失。`target` 可被 Maven clean 清除，正式证据在用户批准本地归档方案后再归档。
