# Jev 与 LLM 路由对比：简历表述

证据日期：2026-10-26；主运行 `jlc04-formal-live-20261026-203132-2b882a`；仅报告数据，暂不判定达标。完整来源见[测试报告](测试报告.md)与[证据索引](证据索引.md)。

## 1. 可直接使用的表述

为多 Agent 系统建设 Jev 结构化路由、置信度门控与 LLM 回退评测；在隔离 Java 路由链路上，以 413 条人工构造样本进行 3 轮对比（每组 1239 次），相较 qwen-plus 主路由，Jev-1.13.0 加回退使路由 P50 从 405.94 ms 降至 211.59 ms、P95 从 722.19 ms 降至 536.62 ms，分别降低 47.88% 和 25.69%；路由阶段 LLM 逻辑调用减少 96.05%，主准确率为 94.75% → 98.47%。

这段中的“建设”适用于你能解释并承担该项目实现与评测工作的情况；若仅负责评测，可将开头改为“设计并实现多 Agent 路由对比评测”。不扩展为线上、首字、完整回答、吞吐或费用优化结论。

## 2. 精简版

构建 Jev 与 qwen-plus 路由评测链路，基于 413 条人工样本完成 3 轮隔离 Java 对比；Jev 加回退的路由 P50/P95 分别降低 47.88%/25.69%，主准确率 94.75%→98.47%，路由 LLM 逻辑调用减少 96.05%。

## 3. 面试时解释口径

测试对象是实际 Java 路由服务，基线是 DashScope qwen-plus，实验是 Jev-1.13.0、0.85 阈值和相同 LLM 回退。并发为 1，固定种子、交替 AB/BA，每轮每组预热 10 次；耗时采用单调时钟，整体 P50/P95 从全部正式完成记录计算，包含失败和安全默认。413 条属于 104 个场景组，3 轮没有扩大独立标注规模。

主准确率只将正常且符合原标签的决策计对，安全默认均计错。LLM 组 1174/1239 正确，Jev 加回退组 1220/1239 正确；安全默认分别 15 次和 7 次。Jev 直接采用 1190 次、尝试 LLM 回退 49 次，其中 7 次回退失败也计入调用数，所以 LLM 调用减少为 1−49/1239=96.05%。BUY Recall 为 242/252→252/252，两组正常 BUY 误报均为 0。

保留集为 60 条、15 组，按组与 development 分开；保留集 3 轮主准确率为 98.33%/100.00%。原始标签有 4 组 16 条争议，保留原标签并单独报告；未宣称业务标签已通过验收。用户选择仅报告数据，暂不作达标决定。

Redis/数据库用测试内存适配，未启动完整应用或业务 Agent，故没有线上生产和聊天首字收益证据。Jev 返回版本为 jev-1.13.0；qwen-plus 是已核实的配置名，响应未给具体后端快照。没有实际账单，不写“成本降低 96.05%”。

第一次正式尝试因采集器误判停止条件中止，原始 25 条及 26 次 HTTP 尝试均保留并计入预算；修复采集器并本地验证后完整重跑，主结果只取新完整运行。能够说明这一点，比隐藏中止或挑选最好一轮更利于复现。
